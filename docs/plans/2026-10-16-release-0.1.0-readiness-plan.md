## Goal

A clean `main` whose verified fixes are committed and whose only remaining steps
are owner decisions plus the already-written publish runbook, so 0.1.0 can be cut
the moment credentials exist.

## Why now

The v1 functional scope is done across eleven packages and the browser UI is
verified working live; the project is unpublished and in limbo. The distance to a
release is no longer features — it is one uncommitted defect, one uncommitted
example fix, and four decisions the owner has not made. Naming those here turns
"ready" from a feeling into a checklist.

## Non-goals

- **ADAPT** — no new runtime capability. The interactive chat surface (T-28), the
  `agent.on` overload (T-29) and `code.delta` (T-30) are post-0.1.0.
- **ADAPT** — no new provider work. The Gemini null-`usageMetadata` hardening
  (T-26) waits on evidence and is not required for a release.
- **ADAPT** — no change to the tool set or the example's fixed transcript; both are
  recorded, not fixed, before 0.1.0.

## Approach

Three short phases. Phase 1 clears the working tree: the example's dev-server
graphics fix and the CLI's dropped-environment fix are already written and
verified, so they are committed with their tests and their lessons. Phase 2 is the
owner's: four divergences (T-16, T-18, T-21, T-25) are confirmation or cadence
choices, each already priced by a research note or a decision record. Phase 3 is
mechanical: `docs/10-runbooks/publish-0.1.0.md` already sequences the release and
is the one irreversible action, so nothing here reimplements it.

## Phases

### Phase 1 — clear the tree

- **Deliverable:** both uncommitted fixes committed with their tests and lessons;
  T-32 closed.
- **Files likely affected:** `examples/vite-app/**`, `packages/cli/**`, `docs/**`.
- **Exit criterion:** the pending tasks are committed and the whole gate is green
  on the committed tree.
- **Verification:** `git status --porcelain` is empty; `pnpm gate` exits 0.

### Phase 2 — take the owner decisions

- **Deliverable:** T-16, T-18, T-21 and T-25 each answered, or explicitly deferred
  with a reason.
- **Files likely affected:** `docs/09-decisions/**`, `docs/04-tasks.md`.
- **Exit criterion:** no task on the board is `pending` only because the owner has
  not chosen.
- **Verification:** the four rows read `done` (with a decision artifact) or
  `blocked` on a named, dated gate.

### Phase 3 — publish 0.1.0

- **Deliverable:** the eleven packages on the registry at 0.1.0.
- **Files likely affected:** `.changeset/**`, `packages/*/package.json`,
  `CHANGELOG.md`.
- **Exit criterion:** a clean consumer installs and imports the facade.
- **Verification:** `npm view smolagents-ts version` answers 0.1.0; the runbook's
  rollback-free check passes; the runbook records its own first-run date.

## Risks

| Risk | Impact | Mitigation | Trigger that means it happened |
|---|---|---|---|
| publishing a tree with the CLI's env defect ships a CLI that silently drops keys | high | Phase 1 commits the fix and its pinning test before Phase 3 | `pnpm vitest run --project cli` fails the "hands the parsed flags and the environment" case |
| a partial publish strands the fixed version group | high | runbook step 4 reviews the bump; `pnpm changeset status` before publish | the six fixed-group packages read different versions |
| a decision is answered to unblock release without its research read | medium | each decision already has a priced note | a decision record appears with no linked research |

## Rollback

Phase 1 is ordinary commits: revert them. Phase 2 changes only documents. Phase 3
is **not reversible** — a published version is immutable; the runbook's forward-only
rollback (`npm deprecate` plus a patch) is the only correction. The checkpoint
before Phase 3 is a green gate on a tree with nothing uncommitted.

stays `in_progress` until the publish run writes its own date.
